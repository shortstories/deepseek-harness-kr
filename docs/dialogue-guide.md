# 대사 추가 가이드 (에이전트용)

대사는 **`assets/dsc-lines.json` 한 파일**에 있습니다. 이 파일만 고치고 검사기를 통과시키면 끝이며, **빌드는 필요 없습니다.**

성격·말투·수위 판단은 [`character-bible.md`](character-bible.md)를 함께 참고하세요.

```powershell
node tools/check-lines.mjs
```

---

## 1. 손대는 파일

| 구분 | 파일 |
|---|---|
| **수정 OK** | `assets/dsc-lines.json` |
| 수정 금지 | `assets/dsc.js`(코드), `lib/client.js`(빌드 산출물), `plugin/*`, `pet/*` |
| 참고 | `_archive/dsc.js.bak`(분리 전 백업) |

- 새 상황 키를 만들려면 코드(`speak("...")` 호출)를 고쳐야 합니다. **대사만 담당하는 에이전트는 기존 키에 줄만 추가**하세요.
- JSON이 깨지면 대사가 통째로 안 나옵니다(코드에 폴백 없음). 반드시 검사기를 돌리세요.

---

## 2. 파일 구조

```json
{
  "text": {
    "hello": "첫 인사",
    "start": "작업 시작",
    "approval": "승인 대기",
    "question": "질문 대기",
    "done": "완료",
    "error": "오류"
  },
  "tools": {
    "명령 실행": "명령 실행 중…",
    "읽기": "파일 읽는 중…"
  },
  "lines": {
    "head": ["[홍조] 대사1", "[><] 대사2"],
    "chest1": ["..."]
  }
}
```

- `text`: 고정 멘트 6개. 문장 하나.
- `tools`: 도구 상태 표시 28개. **감정 없이 "~하는 중…" (10자 안팎)**, 입이 움직이지 않는 상태 표시입니다.
- `lines`: 상황 키 → 대사 배열. **키마다 3개 이상 권장**(직전 대사 회피 로직 때문에 적으면 반복).

## 4. 표정 태그

- 형식: 줄 맨 앞에 `[태그]` 또는 `[태그, 태그]`. 예: `[홍조, ><] …`
- 쓸 수 있는 이름 **8개**: `홍조` `><` `하트` `얄미운` `식은땀` `어두운` `눈물` `어지럼`
- 2개까지 권장. 모르는 이름은 조용히 무시됩니다(오류 없음).
- 태그를 빼면 표정 변화 없음.

---

## 5. 문장 규칙

- **26자 이내**(공백 포함). 말풍선은 `max-width: 230px`, 13px 기준 2줄.
- 해요체. `…`(한 글자) 사용, `...`(마침표 3개) 금지.
- 이모지·`ㅋㅋ`·`ㅠㅠ`·`^^` 금지. `~`, `♪`, `!`, `?`는 허용.
- 같은 키 안 중복 금지, 다른 키와도 중복 비권장.
- **답을 기다리는 질문 금지** — 사용자가 답할 UI가 없습니다. 질문형은 답이 없어도 어색하지 않게.
- 사용자 비하·탓, 실존 인물·정치, 펫이 모르는 사실 단정(작업 내용·결과 평가) 금지.

---

## 6. 수위·톤

- 목표 수위: **NSFW 직전** — 열, 숨, 떨림, 거리, 애원까지. 직접적 행위·신체 묘사, 탈의 묘사는 금지.
- **꼬마 관련 키**(`body_type2`, `walk_*`, `sleep_*`)에는 성적 뉘앙스를 넣지 마세요.
- 옷 방향을 헷갈리지 마세요: 치마 **켜면 길어짐**, 가슴 옷 **켜면 가려짐**. (`skirt_long`/`chest_cover`가 켤 때)
- 캐릭터: 부끄럼 많고 칭찬받고 싶어 함. 삐쳐도 금방 풀리고 사용자를 탓하지 않음.

---

## 7. 추가 절차

1. `assets/dsc-lines.json`을 연다.
2. 해당 키 배열 끝에 문자열을 추가한다. (배열 마지막 원소 뒤 쉼표 주의)
3. 검사: `node tools/check-lines.mjs` → **문제 없음**이어야 함.
4. 반영: 개발 환경이면 새로고침. 펫 창은 숨었다 보이면 다시 읽습니다.
5. 커밋한다면 `assets/dsc-lines.json`을 포함.

---

## 8. 자주 하는 실수

- JSON 마지막 원소 뒤 쉼표(trailing comma), 따옴표 누락, BOM
- 태그를 문장 **끝**에 붙임 → 표정 안 나옴
- 26자 초과 / `...` 사용
- 키 이름 오타 → 그 키는 **조용히 무시**됨(대사가 안 나옴)
- `text`·`tools`에 감정 섞인 긴 문장
- 검사기 없이 저장 → JSON이 깨져 대사 전체가 사라짐

---

## 9. 반영·배포

- `assets/`가 패키지에 포함되므로 JSON도 자동 포함됩니다.
- **플러그인 업데이트 시 `assets/`가 교체되어 수정본이 덮어써질 수 있습니다.** 사용자별 보존이 필요하면 별도 사용자 경로 라우트(2단계)를 추가해야 합니다.
- `lib/client.js`는 코드가 바뀔 때만 `npm run build`로 갱신합니다. 대사만 고칠 땐 불필요.

---

## 10. 프라이버시

- 대사 열람이 금지된 에이전트(기본 규칙상 Opus 등)에게는 **이 파일과 JSON을 넘기지 마세요.**
- 말풍선은 `textContent`로 출력되므로 HTML/스크립트를 넣어도 실행되지 않지만, 데이터에는 문장만 넣으세요.
